# Документация orbiter-lan-coop (OLC)

OLC — плагин для космосимулятора Orbiter, который позволяет нескольким людям летать в одной
симуляции с разных компьютеров в локальной сети. Сейчас проект на стадии исследования:
кода плагина ещё нет, есть архитектура, план и карта ядра Orbiter.

## Для ИИ-агентов и разработчиков

Эта страница — точка входа. Читайте её первой, затем нужный файл из оглавления.
Не сканируйте весь репозиторий заново: карта ниже достаточна.

### Что где лежит

| Файл | Назначение |
|---|---|
| `README.md` | Краткое описание для человека. |
| `CHANGELOG.md` | История изменений. |
| `docs/` | Вся остальная документация. Должна всегда соответствовать коду. |

Исходный код Orbiter в этот репозиторий не входит. Для чтения используется отдельный клон
`orbitersim/orbiter` (у владельца — `~/Documents/github/orbiter`), см. «Условия» ниже.

### Условия, которые нельзя нарушать

1. **Плагин, а не форк.** OLC работает через официальный SDK Orbiter (`Orbitersdk/include`)
   и не требует изменённого ядра. Если без хука в ядре не обойтись — это отдельное решение,
   которое оформляется PR в `orbitersim/orbiter`, а не правкой у себя.
2. **Клон Orbiter только для чтения.** В нём ничего не меняем и не собираем «под себя».
   Карта ядра и все выводы о нём живут здесь, в `docs/ORBITER-INTERNALS.md`.
3. **Базовый коммит Orbiter зафиксирован:** `9721ab8d` (main, 2026-11-03). Все ссылки на код
   ядра в документации указаны для этого коммита. Переход на другой коммит или релиз —
   осознанный шаг с обновлением карты ядра.
4. **Физику считает только хост.** Клиент не принимает решений о движении кораблей: он
   показывает присланное состояние и отправляет ввод. Никакой «своей физики» у клиента.
5. **Только LAN.** Протокол не рассчитан на интернет и не защищён (см. `SECURITY.md`).

### Где что менять

|---|---|

### Правила работы над проектом

- Комментарии в коде и вся документация — на русском. Всё, что плагин пишет в лог Orbiter,
  в окна и в сообщения об ошибках, — на английском.
- Код должен быть простым и понятным новичку: понятность важнее изящества.
- После любого изменения сверьте с кодом `README.md`, `docs/` и комментарии. Они должны
  описывать текущее состояние, а не прошлое.
- Не оставляйте неиспользуемых функций, файлов и зависимостей.
- Сборку и запуск на Windows и Linux выполняет владелец проекта и присылает вывод.
  ИИ-агент проверяет код статически.
- Коммиты и отправку в git делает только владелец проекта. Пока нет релизов, работа идёт
  прямо в `main`.
- Каталог проверочной сборки всегда один и тот же — `orbiter-lan-coop.out` — и он
  перечислен в `.gitignore`.

### Автономная работа

Владелец днём занят, поэтому ИИ-агент работает над проектом сам по пакету задач, который
владелец одобрил. Правила:

1. **Только одобренное.** Агент делает пункты `PLAN.md` и задачи, о которых договорились в
   чате. Всё новое — через вопрос.
2. **Развилка — вопрос, а не догадка.** Вопрос с вариантами и рекомендацией записывается в
   `QUESTIONS.md`, владелец получает уведомление, агент переключается на другую независимую
   задачу. Принятое решение записывается в `DECISIONS.md`.
3. **Нужна Windows или Linux — ждём стенд.** Обходных путей не ищем.
4. **Модели.** Opus — архитектура, постановка задач, проверка результата. Sonnet —
   реализация и разбор кода по готовому заданию. Haiku — поиск по коду. Результат
   субагента Opus всегда проверяет сам.
5. **Лимиты.** Перед каждым куском работы агент смотрит расход:
   - новый кусок не начинается, если 5-часовое окно занято больше чем на 50%;
   - 40% недельного лимита остаются владельцу; расход распределяется равномерно по дням
     до сброса;
   - если порог пройден посреди работы, агент доводит шаг до целого состояния, записывает,
     где остановился, и ждёт следующего окна.
6. **Отчёт.** Каждый пакет заканчивается отчётом: что сделано, что проверено, что нет,
   сколько лимита ушло.
7. **Git.** Агент не коммитит; изменения копятся в рабочей копии, владелец коммитит после
   отчёта.
