# Журнал решений

Принятые решения: что решили, когда и почему. Новое решение дописывается в конец.
Отменённое решение не удаляется, а помечается «отменено» со ссылкой на новое.

| № | Дата | Решение | Почему |
|---|---|---|---|
| 1 | 2026-11-05 | OLC — плагин на официальном SDK, а не форк ядра | Форк быстро отстаёт от `main`; плагин ставится в любой Orbiter |
| 2 | 2026-11-05 | Физику считает только хост, клиенты получают состояния и отправляют ввод | Один мир без расхождений; прошлые попытки (OMP) упирались именно в это |
| 3 | 2026-11-05 | Только LAN, 2–4 человека | Узкая цель для космокружка; без аутентификации и шифрования (см. `SECURITY.md`) |
| 4 | 2026-11-05 | Базовый коммит Orbiter `9721ab8d` (main), цель — следующий официальный релиз | В `main` есть нужное для OLC (столкновения, `oapiGetKeyState`), SDK изменяется только добавлением |
| 5 | 2026-11-05 | Название orbiter-lan-coop, кратко OLC, DLL `OrbiterLanCoop`; лицензия GPLv3 | Коллизии имени OLC проверены; GPLv3 совместима с MIT SDK |
| 6 | 2026-11-05 | Работа прямо в `main` OLC; клон Orbiter только для чтения | Проект в начале пути; карта ядра живёт в `ORBITER-INTERNALS.md` |
| 7 | 2026-11-06 | Порядок работ без Windows: ответы на вопросы этапа 1 по исходникам и шпаргалка SDK → `PROTOCOL.md` (на согласование) → модель сглаживания → сетевое ядро на C++ с тестами на Mac | Это можно сделать и проверить без запуска Orbiter |
| 8 | 2026-11-06 | Задачи, которым нужна Windows или Linux, ждут стенды; обходных путей не ищем | Обходные пути дают неверные выводы и тратят лимит |
| 9 | 2026-11-06 | Пустой плагин и сборка в GitHub Actions готовятся заранее, но считаются сделанными только после зелёной сборки после push владельца | Проверить сборку без Windows можно только в CI |
| 10 | 2026-11-06 | Сеть — свои тонкие обёртки над сокетами, без сторонних библиотек | Трафик простой; меньше зависимостей |
| 11 | 2026-11-06 | Регламент автономной работы ИИ-агента — см. `README.md`, раздел «Автономная работа» | Владелец занят днём; агент работает сам, но не уходит в сторону и бережёт лимит |
| 12 | 2026-11-06 | Состояния кораблей снимаются на хосте и навязываются на клиенте в `clbkPreStep`, а не в `clbkPostStep` | В `clbkPostStep` ядро теряет навязанную ориентацию (два буфера состояния, `ORBITER-INTERNALS.md` раздел 3). Вывод из кода, подтверждается на этапе 1 |
| 13 | 2026-11-07 | Протокол `PROTOCOL.md` согласован как рабочий черновик | Уточняется по замерам модели сглаживания и этапа 1 |
| 14 | 2026-11-07 | Число игроков: цель — 4, верхняя граница — 8 (настройка хоста), больше 8 — вне целей проекта | Сеть не ограничивает; ограничивают нагрузка клиента (растёт примерно как квадрат числа кораблей) и одно общее время на всех |
| 15 | 2026-11-07 | Ускорение времени в этапе 1 — желательный критерий, не обязательный | Стоит почти ничего (поле в каждом пакете), но не должно блокировать прототип |
| 16 | 2026-11-07 | Подключение клиента. Этап 1: тот же сценарий вручную. С этапа 2: кнопка «Подключиться» в Launchpad, хост сохраняет и передаёт текущий сценарий, плагин клиента перезапускает Orbiter с ключом `-s` в этот сценарий и подключается сам; запасной путь — сценарий выделен в Launchpad, один клик. Корабли, появившиеся во время сессии, плагин создаёт сам | Загрузить сценарий из плагина во время работы нельзя; перезапуск даёт точную копию мира, включая состояние дополнений |
| 17 | 2026-11-07 | Дополнения (DLL, модели, текстуры) по сети не передаются: плагин только проверяет и показывает, чего не хватает | Скачивание и запуск чужого кода с любого компьютера в сети — дыра в безопасности; лицензии дополнений часто запрещают распространение. Для кружка — одинаковая сборка на всех компьютерах |
| 18 | 2026-11-07 | Расписание и лимиты автономной работы — см. `README.md`, раздел «Автономная работа» (обновлён) | Владелец работает с проектом в 20:00–00:00 (UTC+5); остальное время свободно для агента |
| 19 | 2026-11-07 | Базовый коммит Orbiter — последний сверенный коммит `main`; сверка с upstream каждый рабочий день (агентом) и перед каждым этапом, порядок — `ORBITER-INTERNALS.md` раздел 13. Агенту разрешено обновлять клон только `git pull --ff-only`. Первый перенос: `9721ab8d` → `b9bd0785` | Не застрять между релизами 2024 и следующим; вовремя заметить изменения SDK и концепции Orbiter |
| 20 | 2026-11-07 | На стендах агент по SSH собирает Orbiter и OLC, запускает и останавливает Orbiter, копирует файлы OLC, читает логи. Установка программ, системные настройки, брандмауэр, снапшоты и docker — только владелец | Итерации этапов 0–1 без ожидания владельца; всё, что может сломать машину, остаётся за ним |
