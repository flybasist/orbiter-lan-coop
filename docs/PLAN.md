# План работ

Цель первой части — **прототип**, который отвечает на вопрос «жизнеспособен ли подход».
Публично о проекте заявляем только после него. Подробный план этапов 2–5 пишется по итогам
этапа 1, когда станут известны реальные проблемы.

## Этапы

| Этап | Результат | Статус |
|---|---|---|
| 0. Стенд | Orbiter собран из базового коммита, пустой плагин загружается, сборка плагина в CI | не начат |
| 1. Проверка идеи | Хост рассылает состояния кораблей, клиент их показывает; общие время и пауза | не начат |
| 2. Наблюдатель | Клиент видит мир хоста, переключает камеру и корабли | — |
| 3. Два корабля (первая рабочая версия) | Каждый управляет своим кораблём; сближение и стыковка двух DeltaGlider на орбите | — |
| 4. Экипаж | Двое в одном корабле: пилот и штурман с MFD | — |
| 5. Для преподавателя | Общая пауза, наблюдение за любым кораблём, сохранение и разбор полёта | — |

Порядок этапов 4 и 5 зависит от ответов космокружка (что им важнее).
Параллельно всем этапам: лог плагина, сетевая статистика (задержка, потери, расхождение
положений), документация.

## Этап 0. Стенд

1. Собрать Orbiter из базового коммита на Windows (см. [QUICKSTART.md](QUICKSTART.md)).
2. Проверить:
   - Parallels (Windows 11 ARM): собирается ли x64, какой FPS у D3D9;
   - Proxmox (Windows x86): эталонная машина;
   - два экземпляра Orbiter на одной машине из разных каталогов — основной режим разработки;
   - запуск без графического клиента (консоль «Orbiter Server Console»);
   - Steam Deck и Linux x86: запуск Orbiter через Proton/Wine.
3. Пустой плагин: загружается, включается во вкладке Modules, пишет строку в `Orbiter.log`.
4. GitHub Actions: сборка плагина на `windows-latest`.

## Этап 1. Проверка идеи

Что делаем:

1. Хост в `clbkPreStep` снимает состояния всех кораблей и рассылает по UDP (20–30 Гц).
2. Клиент в `clbkPreStep` навязывает их кораблям через `DefSetStateEx`.
3. Пауза и ускорение времени следуют за хостом, сим-время подтягивается.
4. Подключение: клиент стартует с того же сценария (вручную или переданного хостом).

**Прототип считается удачным, если:**

- плагин собирается под базовый коммит и загружается в Orbiter;
- хост летает на DeltaGlider, клиент видит движение без заметных рывков;
- расхождение положения корабля на клиенте и хосте на орбите — единицы метров;
- сим-время на клиенте отличается от хоста не больше чем на 0,1 с;
- корабль, стоящий на полосе, на клиенте не прыгает и не проваливается;
- пауза и ускорение времени (до ×100) на хосте сразу видны на клиенте.

Если какой-то пункт упирается в ядро и не решается плагином — это главный найденный риск.
Его оцениваем отдельно (обходной путь или PR в ядро) до продолжения работ.

## Стенды

| Стенд | Для чего |
|---|---|
| Parallels, Windows 11 ARM (Mac) | Быстрые итерации: сборка, один-два экземпляра |
| Proxmox, Windows x86 | Эталонные тесты без эмуляции, несколько машин в одной сети |
| Proxmox, Linux x86 | Клиент через Wine/Proton |
| Steam Deck | Клиент через Proton на реальном железе |
| Парк Windows-машин знакомых, космокружок | Живые тесты, начиная с этапа 3 |

Ubuntu в Parallels — ARM: Wine там требует эмуляции x86, для тестов не используем.
