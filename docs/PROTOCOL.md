# Сетевой протокол OLC

> **Статус: согласованный рабочий черновик** (решение 13 в [DECISIONS.md](DECISIONS.md)).
> Постоянные протокола — в `core/protocol.h`, типы полей — в `core/serialize.h`, заголовки —
> в `core/header.h`, сообщения — в `core/messages.h` (все TCP, кроме `SCENARIO` и `VESSEL_ADDED`;
> UDP пока нет). Документ уточняется по замерам этапа 1.

Как устроен плагин в целом — [ARCHITECTURE.md](ARCHITECTURE.md). Какие функции SDK стоят за
полями — [SDK-CHEATSHEET.md](SDK-CHEATSHEET.md).

## 1. Принципы

1. **Два канала.**
   - **TCP** — для всего, что нельзя потерять: подключение, списки кораблей и тел,
     владение, разовые нажатия клавиш, стыковки.
   - **UDP** — для того, что каждый раз присылается целиком: состояние мира и ввод.
     Потерянный пакет не страшен, следующий его заменяет.
2. **Каждый UDP-пакет самодостаточен.** В нём полное текущее значение, а не изменение.
   Поэтому UDP не нужны подтверждения и повторы.
3. **Имена — по TCP, номера — по UDP.** Хост выдаёт каждому кораблю и телу короткий номер
   (`net_id`) и сообщает соответствие «номер → имя» по TCP. В UDP идут только номера.
   `OBJHANDLE` по сети не передаётся никогда.
4. **Явная сериализация.** Каждое поле пишется и читается отдельной функцией с фиксированным
   размером и порядком байтов little-endian. Структуры C++ целиком в сеть не копируются:
   так формат не зависит от компилятора и выравнивания.
5. **Проверка до разбора.** Пакет с чужой сигнатурой, другой версией, неверной длиной или
   неизвестным номером корабля отбрасывается и учитывается в статистике. Битый пакет не
   должен ронять Orbiter.

## 2. Типы полей

| Тип | Размер | Что это |
|---|---|---|
| `u8`, `u16`, `u32` | 1, 2, 4 байта | Целые без знака, little-endian |
| `f32`, `f64` | 4, 8 байт | Числа IEEE 754, little-endian |
| `str` | 1 + N байт | Длина (`u8`, до 255) и строка UTF-8 без завершающего нуля |

Координаты и скорости — только `f64`: радиус орбиты около 7·10⁶ м, а нужна точность до
миллиметров. Трафик это не нагружает: 30 пакетов по ~1 КБ — около 30 КБ/с.

## 3. Порты и подключение

- Хост слушает **TCP и UDP на одном номере порта**, по умолчанию `47800` (меняется в
  настройках плагина).
- Клиент подключается по TCP, после рукопожатия сообщает свой UDP-порт.

Последовательность:

```
Клиент                                   Хост
  │── TCP connect ─────────────────────────►│
  │── HELLO ───────────────────────────────►│  версия протокола, версия Orbiter, имя игрока
  │◄─────────────────────────── WELCOME ────│  номер клиента, номер сессии, частота состояний
  │                         или REJECT ─────│  причина: версия, мир, места
  │◄──────────────────────────── BODIES ────│  номер → имя для планет и лун
  │◄──────────────────────────── VESSELS ───│  номер → имя, класс для всех кораблей
  │── CLASSES_MISSING ─────────────────────►│  каких классов у клиента нет (может быть пусто)
  │◄────────────────────────── OWNERSHIP ───│  кто каким кораблём управляет
  │── UDP_READY (по TCP) ──────────────────►│  UDP-порт клиента
  │◄═══════════════ WORLD_STATE (UDP) ══════│  20–30 Гц
  │═══ INPUT (UDP) ════════════════════════►│  каждый кадр, не чаще 60 Гц
```

## 4. Заголовки

**TCP** — поток, поэтому каждое сообщение начинается с длины:

| Поле | Тип | Значение |
|---|---|---|
| `length` | `u32` | Длина сообщения после этого поля, не больше 1 МБ |
| `type` | `u8` | Тип сообщения (раздел 5) |

**UDP**:

| Поле | Тип | Значение |
|---|---|---|
| `magic` | 4 байта | `O`, `L`, `C`, `0` |
| `version` | `u16` | Версия протокола, сейчас `1` |
| `type` | `u8` | Тип сообщения (раздел 6) |
| `session` | `u32` | Номер сессии из `WELCOME`; чужие пакеты отбрасываются |
| `seq` | `u32` | Порядковый номер у отправителя; старые и повторные пакеты отбрасываются |

Размер UDP-пакета не больше 1200 байт: такой пакет не дробится ни в одной обычной сети.
Если корабли не помещаются в один `WORLD_STATE`, состояние делится на несколько пакетов
с одинаковым `sim_time`.

**Номера типов** (поле `type`, `core/messages.h`) — по порядку таблиц разделов 5 и 6:

| Канал | Номера |
|---|---|
| TCP | 1 `HELLO`, 2 `WELCOME`, 3 `REJECT`, 4 `SCENARIO`, 5 `BODIES`, 6 `VESSELS`, 7 `VESSEL_ADDED`, 8 `VESSEL_REMOVED`, 9 `CLASSES_MISSING`, 10 `OWNERSHIP`, 11 `UDP_READY`, 12 `KEY`, 13 `DOCK`, 14 `LANDED`, 15 `BYE` |
| UDP | 1 `WORLD_STATE`, 2 `INPUT`, 3 `PING`, 4 `PONG` |

Сообщение с лишними байтами после последнего поля считается битым так же, как обрезанное.

## 5. Сообщения TCP

| Тип | Направление | Поля |
|---|---|---|
| `HELLO` | клиент → хост | `protocol: u16`, `orbiter_version: u32` (`oapiGetOrbiterVersion`), `plugin_version: str`, `player: str` |
| `WELCOME` | хост → клиент | `client_id: u8`, `session: u32`, `state_rate_hz: u8`, `system: str` (имя планетной системы) |
| `REJECT` | хост → клиент | `reason: u8` (1 — версия протокола, 2 — версия Orbiter, 3 — другая система, 4 — нет мест: достигнут предел игроков, по умолчанию 4, не больше 8), `text: str` |
| `SCENARIO` | хост → клиент | `name: str`, `size: u32`, затем `size` байт файла сценария (этап 2; до 1 МБ) |
| `BODIES` | хост → клиент | `count: u16`, затем `net_id: u16`, `name: str` |
| `VESSELS` | хост → клиент | `count: u16`, затем `net_id: u16`, `name: str`, `class: str` |
| `VESSEL_ADDED` | хост → клиент | `net_id: u16`, `name: str`, `class: str`, полное состояние как в `WORLD_STATE` |
| `VESSEL_REMOVED` | хост → клиент | `net_id: u16` |
| `CLASSES_MISSING` | клиент → хост | `count: u16`, затем `class: str` |
| `OWNERSHIP` | хост → клиент | `count: u16`, затем `net_id: u16`, `owner: u8` (0 — хост, 1…254 — клиент, 255 — никто) |
| `UDP_READY` | клиент → хост | `udp_port: u16` |
| `KEY` | клиент → хост | `net_id: u16`, `key: u8` (код `OAPI_KEY_*`), `mods: u8` (биты: 0 — Shift, 1 — Ctrl, 2 — Alt) |
| `DOCK` | хост → клиент | `a: u16`, `port_a: u8`, `b: u16`, `port_b: u8`, `docked: u8` (1 — состыкованы, 0 — расстыкованы) |
| `LANDED` | хост → клиент | `net_id: u16`, `lng: f64`, `lat: f64`, `hdg: f64` (рад) — корабль встал на поверхность |
| `BYE` | любое | `reason: str` |

Разовые нажатия (`KEY`) идут по TCP, потому что потерять «включить автопилот» нельзя.

## 6. Сообщения UDP

### `WORLD_STATE` (хост → клиент)

Общая часть:

| Поле | Тип | Значение |
|---|---|---|
| `sim_time` | `f64` | `oapiGetSimTime` хоста — к этому моменту относятся все состояния |
| `mjd` | `f64` | `oapiGetSimMJD` |
| `warp` | `f64` | Ускорение времени |
| `paused` | `u8` | 1 — пауза |
| `count` | `u8` | Сколько кораблей в пакете |

Для каждого корабля:

| Поле | Тип | Значение |
|---|---|---|
| `net_id` | `u16` | Номер корабля |
| `status` | `u8` | 0 — летит, 1 — стоит на поверхности |
| `ref_body` | `u16` | Номер опорного тела |
| `rpos` | 3 × `f64` | Положение относительно опорного тела, м (только при `status = 0`) |
| `rvel` | 3 × `f64` | Скорость относительно опорного тела, м/с (только при `status = 0`) |
| `arot` | 3 × `f64` | Ориентация, углы Эйлера как в `VESSELSTATUS2` (только при `status = 0`) |
| `vrot` | 3 × `f64` | Угловая скорость, рад/с (только при `status = 0`) |
| `nthr` | `u8` | Число двигателей |
| `thr` | `nthr` × `u8` | Уровни двигателей, 0…255 → 0…1: нужны клиенту, чтобы рисовать выхлоп |

Для `status = 1` положение не передаётся: место посадки клиент получил в `LANDED`.
Топливо в каждом пакете не нужно — раз в секунду отдельным сообщением (будет добавлено
на этапе 3).

### `INPUT` (клиент → хост)

Полное текущее состояние органов управления. Клиент отправляет его каждый кадр, пока
управляет кораблём; хост применяет последнее полученное.

| Поле | Тип | Значение |
|---|---|---|
| `net_id` | `u16` | Корабль, которым управляет клиент |
| `keys` | `u32` | Нажатые сейчас клавиши, биты — раздел 7 |
| `rot` | 3 × `f32` | Джойстик: тангаж, рыскание, крен, −1…1 |
| `lin` | 3 × `f32` | Джойстик: перемещение вверх-вниз, влево-вправо, вперёд-назад, −1…1 |
| `throttle` | `f32` | Ручка газа 0…1; −1 — ручки нет или она не двигалась |

### `PING` и `PONG` (оба направления)

`PING`: `t: f64` — системное время отправителя (`oapiGetSysTime`). `PONG` возвращает его без
изменений. Отправитель получает задержку туда-обратно. Раз в секунду.

## 7. Биты удерживаемых клавиш (`INPUT.keys`)

| Бит | Действие | Бит | Действие |
|---|---|---|---|
| 0–5 | RCS вращение: тангаж +/−, рыскание +/−, крен +/− | 16 | Плавно прибавить газ |
| 6–11 | RCS перемещение: вверх/вниз, влево/вправо, вперёд/назад | 17 | Плавно убавить газ |
| 12 | Малая мощность RCS (Ctrl) | 18, 19 | Зависание больше / меньше |
| 13 | Полный главный | 20, 21 | Триммер вверх / вниз |
| 14 | Полный тормозной | 22, 23 | Тормоз левого / правого колеса |
| 15 | Выключить главный и тормозной | 24–31 | Резерв |

Клиент передаёт **действия**, а не коды клавиш. Поэтому раскладка клавиш на клиенте может
отличаться от хоста.

## 8. Время на клиенте

- Пауза и ускорение берутся из каждого `WORLD_STATE`. Если игрок на клиенте сам поставил
  паузу или изменил ускорение, плагин возвращает значение хоста.
- Клиент показывает мир с небольшой задержкой, интерполируя между принятыми состояниями
  (кубически по положению и скорости). По модели сглаживания: `WORLD_STATE` 30 Гц, задержка
  100 мс; отстаёт весь мир клиента, а не только чужие корабли ([SMOOTHING.md](SMOOTHING.md)).
  Цифры проверяются на этапе 1.
- Если сим-время клиента разошлось с хостом больше чем на 1 с (подбирается), — прыжок
  `oapiSetSimMJD`; иначе мягкая подстройка.

## 9. Версии и совместимость

- `version` в каждом UDP-пакете и `protocol` в `HELLO`. Разные версии не работают вместе:
  хост отвечает `REJECT` с причиной 1.
- Версия Orbiter у хоста и клиента должна совпадать (`REJECT`, причина 2): разные сборки
  могут по-разному считать физику и по-разному хранить состояние.
